## 代码分析：xiaozhi-esp32 1.9.4（小智 AI 固件）
- 用户请求「分析这个代码」，随后选择深入「摄像头识别模块」。
- 项目定位：虾哥开源的 ESP32 AI 语音机器人固件，MCP 协议让大模型控制硬件。
- 分层：main.cc → Application(单例+FreeRTOS 事件循环+状态机) → Protocol(WebSocket/MQTT) + AudioService(音频双流水线) → McpServer(设备 MCP) → boards/display/led(硬件抽象)。
- 摄像头识别模块（用户重点）：
  - `Camera` 抽象接口（camera.h）：Capture / Explain / SetHMirror / SetVFlip / SetExplainUrl。
  - 两实现：Esp32Camera（esp_camera 通用驱动）、SscmaCamera（SenseCAP Watcher 板载 AI）。
  - 接入：`Board::GetCamera()` 默认 nullptr，带摄像头的板子 override + new。
  - MCP：`mcp_server.cc` 仅在有摄像头时注册 `self.camera.take_photo(question)`。
  - 识别非本地推理：拍照 → JPEG 独立线程编码(分块写 FreeRTOS 队列) → HTTP chunked multipart 上传 → 服务器 AI 分析返回 JSON。
- 关键结论：ESP32 太弱跑不动视觉大模型，识别靠云端。

## 追问：如何识别特定人物
- 现状核实：设备端无人脸识别代码（"face" 仅匹配 afe_iface，属音频前端）；SscmaCamera 只取图未用模组识别结果；声纹 3D Speaker 在设备端也未实现。
- 给出三条路线：A 云端人脸识别（自建服务器 + InsightFace/face_recognition + 人脸库，固件零改动，推荐）/ B SSCMA 板载 AI（仅 sensecap-watcher）/ C 声纹识别（服务端）。
- 关键代码：mcp_server.cc ParseCapabilities(147-164) 下发 vision.url；esp32_camera.cc Explain(189) 为设备端上传逻辑。
- 提醒：官方 xiaozhi.me 不支持人脸识别，须自建服务器；人脸数据涉《个人信息保护法》合规。

## 方案定稿：普通 S3 板 + 官方服务器 + 本地识别
- 用户确认：其他带摄像头 S3 板（非 SenseCAP Watcher），走自定义路线。
- 方案：官方服务器继续做语音对话（不动）；只把 Esp32Camera::Explain() 的上传地址硬编码到本地 FastAPI 服务；本地用 InsightFace(CPU/onnxruntime) 比对人脸库 photos/（文件名=人名），返回 {"success","result"}。
- 已给用户完整代码：face_server.py（multipart 兼容 question+file 字段）、固件改法（Explain 开头覆盖 explain_url_）、依赖 pip 清单。
- 已知坑：Windows 装 insightface 需 VS Build Tools；设备与电脑需同网段；防火墙放行 8001；电脑 IP 需固定。
- 备选：若不想装本地模型，可改云 API（腾讯云/百度云人脸识别）版本。
- 注意：该改法会使设备失去官方通用视觉能力，仅保留人脸识别。

## 模型选型澄清（用户问：是 YOLO 吗？要标注吗？）
- 答案：不是 YOLO。face_server.py 用 InsightFace buffalo_l = SCRFD（人脸检测）+ ArcFace（512 维特征）。
- 无需标注/训练：注册式 1:N 比对（photos/ 文件名=人名，每人 1~5 张正脸即可），余弦相似度阈值约 0.5。
- 模型首次运行自动下载（约 300MB，~/.insightface/models/buffalo_l），CPU 单张约 100~300ms。
- YOLO 仅在需要目标检测（有没有人/人在哪/物品检测）时才用，且需标注训练；认人不需要。
